### Findings

- **M1 (major)** `src/frontend/src/shared/ui/dialog/SearchOption.tsx:92-103` — the colour stripe has `height: '60%'` inside a `ListItemButton` whose height is `auto` (only `minHeight`). A percentage height against an indefinite container height computes to `auto`, and the box is empty, so the stripe has **0 px height and never shows**. Headless Chromium, same flex setup (`align-items:center; min-height:48px`) → `height: 0`. The design's 4 px, 60 % stripe (§ 3.1, doc-016 § 3.0), the plan's item 4 and the guide's `stripe` (`ui-kit.md:248`) are therefore not delivered. The test at `SearchOption.test.tsx:52-64` checks only the colour, and jsdom does no layout. Fix: give the stripe a definite height from a token (60 % of `layout.searchOption.height`, e.g. `searchOption.stripeHeight: 28`), or stretch it (`alignSelf: 'stretch'`) with vertical margins of 20 % of the row's height in px. Pin the chosen height value in the test, then look at the `/ui-kit` «Поиск» row with a stripe in a browser.
- **m1 (minor)** `src/frontend/src/shared/ui/fields/SearchField.tsx:114-123` — `role="combobox"` is always set, but `aria-expanded` (a required state of an ARIA 1.2 combobox) appears only if the host passes it. A host that forgets it, and the showcase's second field (`SearchDemo.tsx:91-99`), render an invalid combobox. Fix: default `'aria-expanded': false` before `...passThrough`, or make `aria-expanded` a required prop.
- **m2 (minor)** `src/frontend/src/shared/ui/dialog/SearchPanel.tsx:63-65` — `getBoundingClientRect()` is read during render. The width and the compact `maxHeight` are taken from whatever the layout was at the last render: while the field grows from 300 to 360 px (`transition`) and after a resize, nothing re-renders. Harmless today, because 720 > 360 above the 640 floor. Fix: measure in a Popper modifier, or a `ResizeObserver` on `anchorEl`, or drop `anchorWidth` (it never wins above 392 px).
- **m3 (minor)** `src/frontend/src/shared/ui/dialog/SearchPanel.tsx:105` — compact `width: '100vw'` includes the vertical scrollbar. On a desktop browser narrowed below 700 px with a classic scrollbar, the full-width panel is wider than the visible area and can add a horizontal page scroll. Fix: in compact, use the anchor's (the header's) width, or `100%` of the viewport's client width.
- **m4 (minor)** `src/frontend/src/features/uikit/showcase/demos/SearchDemo.tsx:90-99` — the highlight demo uses `SearchField` as a plain query input: a combobox with no popup, no `aria-expanded` and no `aria-controls`. The showcase is where hosts copy from. Fix: drive the highlight demo with a kit `InlineTextField`, or reuse the first field's value.
