## Misses

The session and realm security model (0022, 0033) running in production on unaccepted ADRs is itself a governance gap. It belongs in the gate-1 questions.
- **M-2.** ARC (ADR conformance): ADR-0031 claims 'Departures from docs/conventions/*: none' (docs/adr/0031-typed-area-tree.md:82) while prescribing numeric type values (:39), against docs/conventions/backend.md:314-318. The analysis reports the symptom (ARC-3) as a code defect instead of an inconsistency inside an accepted ADR.
- **M-3.** ASY/TXN: the standard resilience handler applied to every HttpClient (src/backend/Mustask.ServiceDefaults/Extensions.cs:33-36) can retry the non-idempotent refresh_token POST (src/backend/Mustask.Api/Features/Session/RefreshGrantClient.cs:55-71). Under the realm's rotation and reuse detection (docs/adr/0022-token-mediating-backend-for-the-panel.md:52-71, D-14), a retry after a committed-but-failed first attempt ends the user's session. The analysis checked this case and called it harmless (ASY-4).

## Overall

The analysis is accurate on its facts. Nearly every cited line exists and says what the analysis says it does. Where it falls down is severity, and it treats a few canon-sanctioned patterns as defects. Two of the four majors survive. SEC-1 stays major on the azp half. The ADR-0033 'contradiction' is closer to an ambiguity that rule 2 resolves, and ADR-0033 is only proposed. SEC-2 also stays major, but its framing is overstated: the refresh-token protection holds, and what widens is who can mint access tokens on the shared origin. The two architecture majors fall to minor: the link rule is bounded, the grants example is wrong and the proposed signature does not fit the lock pattern (ARC-1), and the four interfaces are not a breach (ARC-2). ARC-3 is refuted as a defect, because accepted ADR-0031:39 prescribes the numeric type values. ERR-3 runs against ADR-0004:111-128, which sanctions http.bad_request, and its 'order leak' is wrong. ARC-5 misquotes backend.md:219-226, which allows bulk raw SQL. ASY-4 goes the other way and moves up to minor: retrying the refresh POST can end the session under the D-14 reuse rule. Several 'clean today' guardrail items rated minor become info by the analysis's own scale: ASY-1, DEP-3, DEP-5 and ERR-2. Three misses: implemented ADRs that are still 'proposed' (0021/0022/0033/0034/0036), ADR-0031's false 'no departures' line, and the refresh-retry hazard. The task table needs re-sizing: #3 toward L, #10 and #14 to M, #13 split. #5 and #11 should be dropped or parked. The corrected tally is 0 blockers, 2 majors (SEC-1, SEC-2), roughly 17 minors and roughly 26 infos. Verdict: needs-human-decision. Three questions are for the human: SEC-2 risk acceptance or own origin, the SEC-1 user-gate policy, and whether to accept the proposed ADRs.
