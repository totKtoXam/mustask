## Plan

<!-- S/M: implementation plan, 3-10 lines. L: see plan-backend.md / plan-frontend.md -->

Backend, both passes; no lanes (three use cases sharing one membership read). Contract: [api-contract.md](api-contract.md).

1. **Domain `Boards`** (pure, unit-tested): `BoardLevel` (`epics`/`features`/`stories` → a process level by kind and rank), `StackRank` (placed by place, then unplaced by number; a move to the top / bottom / after an item; a missing item or anchor throws `boards.backlog.reorder_stale`), `BoardLayout` (BR-M4-2's columns from the level's types and states), `BoardErrorCodes`; the permission code `boards.backlog.reorder` in `OrganizationPermissionCatalog`.
2. **Membership, one query shape** (`Infrastructure/Boards/BacklogMembership`): the team's areas are the project's area nodes whose `AreaTree.ResolveOwner` is the team (mod-002's own rule, no second copy), then one `work_items` query on project, level's types, those areas and the level's non-Removed states, left-joined to the item's place on this backlog. A new index `(project_id, type_id, area_id)` serves it; the backlog read, the board read and the reorder all call it.
3. **Storage, migration `AddBoards`**: `backlog_orders (team_id, backlog_level_id)`, a row per reordered backlog, the reorder's lock; `backlog_places (work_item_id PK, team_id, backlog_level_id, position)` — one place per item, so placing it on another backlog moves its one row. Nothing backfilled (BR-M4-13).
4. **Slices `Features/Boards`**: `GetBacklog`, `ReorderBacklog` (204), `GetBoard`, routes under `…/teams/{teamId}/backlogs|boards/{level}`; address via `IOrganizationStructure`, level via mod-001's process read. Card move = mod-003's PATCH `{ stateId }`, unchanged.
5. **Concurrency (ADR-0011)**: a reorder locks the team `FOR SHARE` (re-checks it is active; a deletion waits), then its `backlog_orders` row `FOR UPDATE` (echelon 3), then reads the order — reorders of one backlog run one after another, each on the committed order of the one before. Places are written by one set-based delete (`team, level`, not a member) and one upsert on `work_item_id`, so a concurrent reorder of another backlog that takes or drops the same item's row waits on that row and re-evaluates.
6. **mod-003 create, additive**: optional `teamId`; after the counter lock and the replay check, the team `FOR SHARE` (active, of the project, else `organizations.team.not_found`), its default area read under that lock (a default change takes the team `FOR NO KEY UPDATE`, so it cannot move meanwhile); no `teamId` keeps the root.
7. **Tests**: domain units; one integration class per route (Testcontainers), US-1..US-7 scenarios named in comments, a commit-gate race for two reorders, a 5 000-item volume check; catalog, permission, inventory and OpenAPI tests extended.

Frontend, two passes (A the backlog, B the board), one slice `features/boards` for both pages, as the backend's `Features/Boards`:

1. **API layer** `boards/api`: `getBacklog`, `reorderBacklog`, `getBoard` per api-contract § 2–§ 3; keys `['boards', 'backlog' | 'board', org, project, team, level]`, both of a team read again after every write. The card move and the creation are mod-003's writes through its barrel: `useCreateWorkItem` (body gains the optional `teamId`, § 7) and a new `useSetWorkItemState` (PATCH `{ stateId }`); `boards.*` codes as constants in `shared/api/errorCodes.ts` with a drift test.
2. **Pages and routes**: `BacklogPage` at `…/teams/:teamId/backlogs/:level`, `BoardPage` at `…/teams/:teamId/boards/:level`, registered in `app/routes.tsx`; an unknown `:level` answers «Страница не найдена», the address's not-found codes their frames; entries «Доски» (pass B) and «Бэклоги» (pass A), team scope, `workitems.workitem.read`, after «Рабочие элементы» in `app/navigation/model.ts`.
3. **Pure logic** `boards/lib`: `reorder.ts` (menu entry or drop gap → `top` / `bottom` / `after`, the disabled entries, the optimistic order renumbered), `board.ts` (a card's target per column, the menu's columns, the optimistic board with the card at its rank).
4. **Components, MUI core only**: `PageHeader` with the level tabs as addresses and the cross-link; the backlog `Table size="small"` with `DragIndicator` `IconButton` handles and their `Menu`; the board `Box component="section"`, columns at `layout.boardColumnWidth`, `Card` with the type stripe, the `MoreHoriz` card `Menu` with a `ListSubheader`; `StateFrame`, `RegistrySkeleton` / `Skeleton`, `ErrorBanner`, `Snackbar` + `Alert`; a visually hidden `role="status"` for the announcements.
5. **State**: server state in TanStack Query (read again on focus, BR-M4-28); client state per page in `useState` — the optimistic order or board while a move is saved, the drag in progress, the open menu or dialog.
6. **Drag**: the browser's native HTML drag and drop, by the orchestrator's decision (no library, which would need an ADR); the keyboard menus are the complete, authoritative path.
7. **mod-003 reuse**: `CreateWorkItemDialog` takes its types as `{ id, name, appearance, initialStateName }` and gains an optional `team` (name, default-area path) that changes its text and skips the area-tree read; on the project's list nothing changes. `TypePickerMenu` and the `TypeName` / `StateName` / `AssigneeName` marks are exported through the barrel.
8. **Tests**: units on `lib/`; component tests per US-1..US-7 scenario on an in-memory API (`boards/testApi.ts`); a routes test in `app/`; the navigation tests and E2E 19.5 brought in line; E2E `23-backlogs-boards.spec.ts` on the menu paths.
