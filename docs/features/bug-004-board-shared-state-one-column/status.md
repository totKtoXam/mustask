## Plan

1. Seed (`Mustask.Domain/Process/SeededProcess.cs`): «Разрешена» is Resolved on Эпик, Фича, Пользовательская история and Баг — one blueprint state; `ResolvedInProgress` goes. The seeded counts do not change (5 types, 24 states).
2. The rule «a state name has one category on every type of the process» in the domain: `ProcessBlueprint.EnsureValid` refuses a breach (so the seed is tested against it at every seed), and `ProcessDefinition` gets the same check on the built aggregate. The only code that creates a state is `ProcessDefinition.Seed` (`WorkItemType.AddState` is internal; no endpoint, handler or command adds or renames a state — doc-007's customization is not built), so the rule is pinned there and in the tests, not in a handler.
3. EF migration `MoveResolvedToResolvedCategory` (data only, snapshot unchanged): moves the rows still as seeded — type key EPIC/FEAT/US, state «Разрешена», position 3, category InProgress — to Resolved; a `RAISE WARNING` names every process in which a state name still has two categories afterwards (reported, not guessed); `Down` is the mirror on the same predicate and leaves BUG alone. Idempotent by its predicate.
4. Board headers (`Mustask.Domain/Boards/BoardLayout.cs`): every column is headed by the name of the state it maps for the first type, in display order, that maps one; the category labels leave the headers (the response's `category` object per column stays, it is not a header). Unit tests: seeded process on all three levels, a process whose types' labels differ, a process with two states of a category.
5. Backend tests rewritten, not deleted: `SeededProcessTests`, `ProcessBlueprintTests` (+ the rule), `BoardLayoutTests`, `GetBoardEndpointTests` (read and card moves), `CreateFromTeamEndpointTests`, `GetProcessDefinition` handler and endpoint tests; new `MoveResolvedToResolvedCategoryMigrationTests` (Infrastructure.Tests, Testcontainers): a seeded organization, one whose «Разрешена» was changed by hand, one renamed; Down; Up again.
6. Frontend: `boards/testApi.ts` derives headers by state name; `process/testFixtures.ts` seeds «Разрешена» as Resolved on the four types; `BoardPage.tsx` empty hint names the first column by the board's own header instead of «Новые»; tests of `boards/` and `process/` rewritten to «Новая», «Активна», «Разрешена», «Закрыта»; a test pins the story's «Разрешена» dot to the Resolved colour.
7. Notes (superseded in part): doc-007 spec («One label, two categories»), mod-001 (spec/api-contract § 1.4 and design), mod-006 (spec columns rule, BR-M4-2, US-4, US-5, api-contract example), mod-015 design (Columns' default headers); contract examples that change are listed in this status.
8. Not touched: `src/frontend/e2e/` — every E2E line that names the old headers or the story's category is listed in the report for the QA agent.

New rule, applied after the per-category columns are derived: columns whose mapped states carry one label, where no type maps a state in more than one of them, become one column; it stands where the first of them stood, is headed by that label, and a drop writes, per type, the state that type maps there. The response's shape does not change, only its column list; an api-contract example that lists the old columns is corrected with a note here. Tests: the derivation's unit tests, the board read's integration tests, frontend tests that hard-code the columns, E2E 23 aligned and run; mod-006 spec, US-4 and US-5 get a superseded-in-part note. - D-3 (human 2026-10-12, in chat and through AskUserQuestion): «не только в одну колонку, в целом не вижу смысла от двух разных статусов, описывающее одно и тоже» → «Одно имя — один смысл». Supersedes D-2's rule; D-2's cause stands. (1) «Разрешена» means one thing on every type — done, awaiting verification: on Эпик, Фича and Пользовательская история it moves from InProgress to Resolved, as on Баг; the seed changes and a migration moves the existing organizations' processes (only states still as seeded; anything else is reported, not guessed). (2) One rule for the whole process: a state name has one category on every type of the process; the seed is tested against it, and any write path that creates or renames a state refuses a breach. (3) Board columns are headed by state names, as the reference does: the k-th column of a category is headed by the label of the state it maps (the types' shared label; if they differ, the first type's in display order — mod-006's existing tie rule); category labels («Новые», «В работе», «Решённые», «Завершённые») leave the board and stay in the process settings and wherever a category is shown. Seeded result: «Эпики», «Фичи» and «Истории» → «Новая», «Активна», «Разрешена», «Закрыта». (4) Everything that reads the category follows: the state dot's colour of «Разрешена» on a story becomes the Resolved colour; counts and filters by category. (5) Superseded-in-part notes in doc-007 (One label, two categories), mod-001 (the seed table and its contract example), mod-006 (the columns rule, US-4, US-5, the contract's example) and mod-015 design (Columns' default headers). E2E 23 and any spec that names the old headers are aligned and run. Size M; one review round.
